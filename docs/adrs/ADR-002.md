# ADR-002: Repository layout, flat Python packaging, and single-deployable pipeline

- **Status:** Accepted
- **Date:** 2026-09-13
- **Deciders:** Founder (CEO)
- **Context PBI:** PBI-001 (`specs/app-foundation/spec.md`)

## Context

SWE Drip V1 is a clean-room polyglot monorepo: a Next.js 15 Control Panel, a
FastAPI Control Panel API, a LangGraph pipeline, and collection-contract YAML.
The technical spec calls for the pipeline and API to ship as one backend unit
(the pipeline is invoked by the API through the LangGraph checkpointer) and for
the frontend to talk only to the API. We need a layout that keeps those
boundaries obvious and keeps gate commands simple.

## Decision

1. **Top-level layout is fixed** (per `specs/app-foundation/spec.md` C1):
   - `control-panel/` — Next.js 15 (App Router, TypeScript) + shadcn/ui.
   - `api/` — FastAPI application, import target `api.app.main:app`.
   - `pipeline/` — LangGraph `StateGraph` package, importable by the API.
   - `collections/` — runtime collection-contract YAML.
   - `docs/`, `specs/`, `tasks/`, `plans/`, `scripts/`, `tests/` — spec kit,
     planning artifacts, and the root docs-contract gates.
2. **Flat Python packaging**: a single root `pyproject.toml` installs the `api`
   and `pipeline` packages (no nested `src/`), so `api.app.main:app` and
   `import pipeline` are stable and one `pip install -e ".[dev]"` provisions the
   backend.
3. **Single deployable backend**: the pipeline is a library consumed by the API,
   not a separate service. Control Panel → API → (checkpointer | pipeline) is the
   only request path.
4. **Control Panel is an independent Node project** with its own `package.json`;
   the root project remains the docs-contract gate and orchestrates the polyglot
   `verify` chain (PBI-003).

## Consequences

- Later PBIs must not add top-level app directories without a superseding ADR.
- The `api.app.main:app` / `import pipeline` import paths are stable contracts.
- The root `package.json` never becomes the Control Panel's manifest; each stack
  owns its own toolchain and lockfile.
- Splitting the pipeline into a separate deployable would require a new ADR.

## Alternatives considered

- **Nested `src/` layout (backend/src/api, backend/src/pipeline)** — rejected:
  more path ceremony, no benefit at this size.
- **Separate pipeline service (its own deployable)** — rejected for V1: the
  Control Panel only reads through the checkpointer, so a second process adds
  ops surface without a requirement.
- **Single Next.js app hosting Python via serverless** — rejected: violates the
  FastAPI + LangGraph target and would fragment the runtime.
