# ADR-004: Product-create mechanism — MCP write tool vs hand-rolled Open API (A13)

- **Status:** Proposed (pending live spike — founder runs `scripts/fw_create_spike.py --live`)
- **Date:** 2026-09-14
- **Deciders:** Founder (CEO)
- **Context PBI:** PBI-026 (`specs/fourthwall-integration/spec.md`, contract C2)

## Context

The pipeline's FW-create node (PBI-014) currently drafts products through an
injected client with a hardcoded DRAFT payload. For the v1 publish cutover
(PBI-027) we must settle the single write path (CC-2): the official
Fourthwall MCP product-create tool, or a hand-rolled Open API flow
(signed-URL artwork upload + product create). The spike harness
(`scripts/fw_create_spike.py`) exercises the MCP tool against the placement
matrix (front/back/sleeve, multi-region, colorways) and records which
placement fields survive.

## Decision (conditional — confirmed by the live run)

- **If the MCP create tool covers the full matrix** (every case
  `full_coverage: true` in the live evidence): v1 ships the MCP write tool
  behind the pipeline's injected Fourthwall interface. No second path.
- **Else (tool missing, or any field dropped/unsupported):** v1 ships the
  hand-rolled Open API flow (signed-URL upload + create), implemented once
  behind the same injected interface. No MCP write calls in production.
- **Partial coverage never ships as a hybrid in production.** Per the PBI-026
  refinement rule, mixing both mechanisms is a second write path (CC-2
  violation) unless a follow-up ADR explicitly scopes a hybrid behind the
  single entry point. The spike's `coverage_of` matrix is the evidence that
  forces one side or the other.

Whichever wins: DRAFT-first (PBI-014 behavior preserved), Shelf
price-invariants enforced before the write call (C6), prices derived from the
shelf/contract at the call site (never literals), credentials server-side only
(C7), and the Control Panel gains no product-create path (C3).

## Consequences

- PBI-027 implements exactly the decided mechanism; the other path is not built.
- The live evidence (tool names seen, per-case kept/dropped fields, raw
  request/response shapes) is pasted into the Evidence section below and the
  assumed MCP tool names in `api/app/fourthwall/client.py` are corrected to
  the observed schemas.
- If Fourthwall later ships a covering MCP write tool, a new ADR (not silent
  code) moves v1 onto it.

## Alternatives considered

- **MCP write unconditionally** — rejected without evidence: assuming write
  coverage is an explicit anti-pattern (spec).
- **Hand-rolled Open API unconditionally** — rejected without evidence: if the
  MCP tool covers the matrix it is less code to own and stays on the official
  surface.
- **Both, routed per case** — rejected for v1: second write path, dual-write
  risk, untestable matrix routing.
