# ADR-006: Operator MCP doorway — in-process FastMCP, scoped Bearer tokens

- **Status:** Accepted
- **Date:** 2026-09-16
- **Deciders:** Founder (CEO)
- **Context PBI:** operator-mcp epic (PBI-043…046); implements
  `specs/operator-mcp/spec.md`

## Context

Test, calibration, and tuning loops need machine access to the pipeline:
trigger runs, read runs/logs/approvals/agents/catalog/audit/calibration,
and tune per-node runtime config — remotely, without container access or a
browser session. Better Auth cookies serve browsers only, and the ADR-005
lesson applies to ourselves: interactive OAuth flows do not serve machine
clients. A second doorway was needed with the same enforcement as the
Control Panel UI.

## Decision

1. **Transport:** the official `modelcontextprotocol/python-sdk` (v2,
   `MCPServer` — the v1 `FastMCP` name), Streamable HTTP, **in-process**,
   mounted at `/mcp` in the existing FastAPI app. No new hosting process,
   no new database. Stateless single-JSON responses (every tool is a quick
   query); the session manager runs on the outer app lifespan because
   mounted sub-app lifespans do not cascade in this stack (verified by
   probe — otherwise every request 500s).
2. **Auth:** scoped long-lived Bearer tokens (`sdr_` prefix), `sha256(salt +
   token)` at rest, `read` vs `operate` scopes. Issued/revoked Admin-only
   via `POST /api/operator-tokens[...]` with prefix-only audit. No
   OAuth/DCR, no session cookies on `/mcp`.
3. **Reads mirror REST:** tools call the router endpoint functions directly —
   shapes identical by construction, never re-implemented.
4. **Writes reuse services:** run start, approval decide, agent config, and
   replay go through the same functions (brief validation, $130 guard,
   catalog checks, cost notes, audit). Scope-at-boundary is the enforcement;
   `operate` scope is admin-issued, so it authorizes every write the tools
   offer; audit rows carry the token identity.
5. **Graph inspection is read-only:** order, edges, state keys, live config
   sources. Structural mutation (add/remove/reorder/rewire) is never
   exposed — the locked 11-node order stays a code + spec-amendment path.

## Alternatives considered

- **Stand-alone MCP process:** rejected — a second deployable doubles the
  ops surface (deploy, env, logs) for tools that are thin wrappers over
  in-process functions; in-process mounting keeps one Coolify app.
- **OAuth/DCR login flows:** rejected per ADR-005's own lesson — machine
  clients cannot complete browser logins; static scoped tokens with
  issuance-as-human-gate fit the threat model.
- **SSE streaming transport:** rejected for now — stateless request/response
  covers every tool (all quick queries); live log streaming stays on the
  existing SSE endpoint.

## Consequences

- `/mcp` is a second production attack surface: Bearer-gated, scope-gated
  per tool, audited writes. Token issuance/rotation discipline lives in
  `DEPLOY.md` (operator runbook).
- SDK major upgrades (v1→v2 rename already absorbed) must re-run the
  loopback conformance suite (`api/tests/test_mcp_reads.py`,
  `api/tests/test_mcp_writes.py`).
- Structural graph edits remain code changes — any future request reopens
  this ADR, it does not extend the toolset silently.
