# PBI-037: Pipeline run initiation — start a run from the Control Panel

## Directive

Add the pipeline's missing entry point:

1. `api/app/runs.py` — a `RunStarter` protocol plus `CheckpointerRunStarter` (prod): generate `run_id` (`uuid4().hex`), build the graph over the shared checkpointer saver, and `invoke` the initial state on a **background thread** so the request never blocks. Config assembled from the running system: `hitl` = `api.app.settings_store.get_hitl_flags()`, `llm_client` = `pipeline.llm.OpenRouterClient()`, `cost_engine` = `api.app.db.get_engine()`, `run_dir` = `<runs_root>/<design_id>` (the same root `routers/designs.py:get_runs_root()` serves renders from). Never set `fw_live`; never inject a Fourthwall write client.
2. `api/app/routers/runs.py` — `POST /api/runs` (Admin/Operator), body `{collection_id, design_id?, briefs?}`, `202` `{run_id, status, collection_id, design_id}`, audit `run.start`, `409` when month-to-date spend ≥ `agents.GLOBAL_MONTHLY_CAP`.
3. Tests: start returns 202 + the run appears in `GET /api/runs`; role matrix (Viewer 403); cap refusal; audit row; **no `fw_live`/`fw_client` reachable from the start path** (assert the assembled config); background execution does not block the response (a stubbed slow graph returns promptly); `design_id` defaults to the run id.

Scope boundaries: no Fourthwall publish/write path (PBI-027); no scheduler; no new run-state store — the checkpointer remains the single source (NFR-1); do not change the approve→resume semantics of collection approval.

- If a live run must be started with `fw_client` injected to get past node 9, stop: that is PBI-027's decision (ADR-004), not a run-start concern.

## Live-run findings (2026-09-15)

The first live run executed nodes 1–9 and paused at `publish_gate`, which validated the whole start path — and exposed three defects, all fixed here:

1. **`briefs` are required** (empty set → 8 cascading node errors). Now validated at the API boundary with the locked score ranges; spec Decisions updated.
2. **`GET /api/approvals` hung** (25s+ timeout) whenever a paused run existed: `list_interrupts` called `graph.get_state()` *inside* the `saver.list(None)` iteration, blocking the saver pool. Split into list-then-query phases, with a regression test that fails if a query is issued mid-list. This was the blocker for A7 — the approvals queue is the only surface that can act on a paused run.
3. **`GET /api/runs/{id}` and `GET /api/runs` disagreed** on status for a paused run (`failed` vs `awaiting_approval`) because `run_detail` hardcoded `interrupted=False`; the interrupt flag now rides on `Snapshot`.

Also noted (not fixed here): with the pipeline paused at `publish_gate` doing nothing else, `art_render` never reached a model call because it had already errored upstream, so live model spend is still $0 — meaning the OpenRouter call path itself remains unproven in production.
