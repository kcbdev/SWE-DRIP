# PBI-050: Collection-research graph (synthesize → board → draft → gate)

## Directive

Build the monthly-cadence creative graph that produces locked contracts:

1. `pipeline/collection_graph.py` (new) — locked node order
   `inspiration_review → style_synthesis → mood_board → contract_draft →
   collection_gate`, assembled like `pipeline/graph.py` (register + build,
   checkpointer-backed, `interrupt()` gate at the end with CEO approve /
   edit-and-approve / reject). Monthly cadence is operational (run on
   demand), never a scheduler in this PBI.
2. Nodes (new, `pipeline/nodes/research_*.py` + registry):
   - synthesis reads the collection's inspiration assets + lineage
     (PBI-051 provides the record; until then it accepts an explicit
     `avoid` input) and proposes locked directives
     (`style_descriptors`, palette justification, `avoid`) via the routed
     model — recorded with a `prompt_version` (agent-control-plane rule).
   - mood render generates the board sheet via the image model into the
     collection's `.assets/` (style samples, never products), bumping
     `board_version`.
   - draft assembles the v2 contract (empty where unknowable — same
     no-invention rule as node 2) and pauses at the CEO gate.
3. Drafts enter the existing collections lifecycle (candidates → approve →
   active via PBI-020); the graph never writes `active` directly. Run
   logging, cost rows, and config resolution reuse the item-graph patterns
   (runlog, costs, node_config) — no parallel implementations.
4. Tests: offline graph run with fakes (synthesis text captured, board
   bytes validated PNG, draft shape-valid, gate interrupts with the draft
   payload, resume approves); no-invention assertions (empty fields stay
   empty); cost rows written per model call.

Scope boundaries: no QC/diversity enforcement (PBI-051); no ingest UI
(PBI-049 is API; UI is PBI-052); no scheduler/cron; no web harvesting.
