# PBI-051: Style-conformance QC + diversity check + rotation queue

## Directive

Enforce coherence within collections and diversity between them:

1. `pipeline/rubric.py` — fifth criterion `style_conformance` (scored
   against the collection's mood board, not the text prompt; same 0–100
   scale and ≥70 pass rule). `RUBRIC_VERSION` bumps (existing convention)
   and the QC `prompt_version` chain covers the new builder text.
   Thresholds stay code constants (PBI-039 boundary respected).
2. `pipeline/nodes/aesthetic_qc.py` — vision call carries the board image
   alongside the render (data-URI pattern already proven); verdict records
   `board_version`; a composition-passing but style-betraying render fails
   with the criterion named. Missing board → explicit `unscored` marker
   (never a guessed pass) so pre-board collections keep running honestly.
3. Diversity: `pipeline/lineage.py` (new) — record of past archetypes,
   palettes, motifs from active/retired contracts; synthesis input as
   negative context; a draft-time check flags near-duplicates (shared
   archetype + overlapping palette/motifs) with reasons instead of
   approving silently. Rotation queue: the runs-equivalent listing
   surfaces the next queued candidate so rotation never stalls.
4. Calibration: new pins exercising the fifth criterion (pass + fail),
   pin-version match tests extended; existing ninja/rocket pins keep
   passing (their verdicts predate boards → `unscored`, agreement logic
   treats like-with-like per PBI-039).

Scope boundaries: no research-graph changes (PBI-050); no threshold
retuning (70 stays); no auto-retire (recommendations only — founder
authority per hitl-graduation).

  criterion makes a pin unusable, say so in the calibration view — never
