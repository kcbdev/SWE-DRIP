# PBI-045: MCP write tools (runs, approvals, agent config, replay)

## Directive

Give the operator doorway the production writes — through the same enforcement
as the Control Panel, never around it:

1. `api/app/mcp/tools_writes.py` — `operate`-scoped tools that call the
   service layer directly: `run_start(collection_id, briefs, design_id?,
   design_type?)` → `CheckpointerRunStarter` (brief validation, $130 cost
   guard 409, phase lock, `run.start` audit); `approval_decide(...)` → HITL
   decide path (exactly-once, audited); `agent_config(node, {cap_usd?, model?,
   params?, enabled?, prompt_override?, cost_impact_note!})` → the same
   validation as `PATCH /api/agents/{node}/config` (catalog 422 + suggestions,
   503 unverifiable, 4-node prompt allowlist, cost note required, versioned
   prompt audit); `run_replay(run_id, node)` → replay path (audited).
   Every rejection the REST layer produces is reproduced with the same
   meaning; every mutation writes its audit row with the token's actor.
2. Registration in `api/app/mcp/server.py` (sequential after PBI-044 —
   shared assembly point, no parallel edit).
3. Tests `api/tests/test_mcp_writes.py` — offline over in-memory transport
   with fakes: `read`-scoped token gets 403 on writes; dead model ID → 422
   with suggestions; missing cost note → 400; spend over cap → 409; audit
   rows recorded with token actor; run start returns a run id without
   executing the graph (fake starter).

Scope boundaries: no new write semantics (any behavior the REST layer lacks
is a spec gap, not a silent addition); no structural graph tools (spec C4);
no per-run ad-hoc overrides bypassing the store.
