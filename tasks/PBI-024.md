# PBI-024: Design QC screen

## Directive

Build the Design QC screen: queue list (deep-linked from Approvals) and detail view with the large render preview, four score bars with the threshold marker, colorway swatches (valid vs invalid with contrast-fail reason on hover), approve / reject-with-required-note / regenerate-with-edited-note actions (via the HITL decision API), and the calibration indicator (human decision vs rubric verdict). Optimistic pending states and error recovery per the Approvals patterns.

Scope boundaries: no rubric scoring in the client; no second decision path; queue mechanics come from the approvals API (filtered to Designs).

## Verification

- Executable: component tests with mocked API (scores render with threshold; swatch validity + reasons; reject requires note; regenerate carries the edited note; calibration indicator states); `cmd /c "npm run verify"` green.
- Manual: review a QC-paused design end-to-end: approve → pipeline continues; reject with note → regeneration request recorded.
