# PBI-019: Collection YAML store + CRUD API

## Directive

Implement `api/app/collections_store.py` (validated read/write for `/collections/<slug>.yaml`, atomic writes, mtime tracking, schema validation via a pydantic model mirroring data spec §1.1) and the CRUD API: `GET /api/collections` (filter by status, Viewer+), `GET /api/collections/{id}` (Viewer+), `POST /api/collections` (draft, Admin), `PATCH /api/collections/{id}` (Admin). Every write writes an audit row via the shared writer. Tests: round-trip read/write; field-level validation errors; unknown-field rejection; atomic write behavior; audit row per mutation; role matrix.

Scope boundaries: no lifecycle transitions (PBI-020); no UI (PBI-021); do not store contract content in Postgres. You may refactor `api/app/routers/dashboard.py`'s inline collections glob onto this store — response shape must not change.

- Depends on: PBI-004 (RBAC), PBI-006 (audit writer), PBI-008 (dashboard consumer, optional refactor)

## Verification

- Contracts C1, C2, C5, C6 of the spec.

- Manual: create a draft via API → file appears under `collections/`; edit field → file updates and audit row records before/after.

## Refinement rule

- Slug rules: lowercase kebab-case, unique; a collision is a validation error, not an overwrite.
