# PBI-058: One-shot research runner CLI (ops live run)

## Directive

Run a real research graph where the models, database, and volumes live
(production container) without moving secrets anywhere:

1. `pipeline/research_cli.py` — `python -m pipeline.research_cli SLUG
   [--demo]`: builds the run input through the validated stores
   (`build_research_state`), then invokes `build_collection_graph` with
   the production runtime (OpenRouter client from env, Postgres
   checkpointer + cost engine, `SqlRunLogger`, durable asset root).
   Thread id carries the `rsch_` prefix so the run is visible in
   `/api/research/runs`; HITL stays at research defaults (gate ON) so a
   live run pauses for the founder's UI approval instead of auto-deciding.
   Prints a JSON summary (run_id, stage, board ref/version, draft id,
   flags, spend rows written).
2. `--demo` seeds a clearly-named `live-review` draft (full valid
   contract + one link ref) through `CollectionsStore.create` — refuses
   with a loud error when it already exists (never overwrites). No other
   magic data: the file content is hand-authored in the module.
3. No auto-run anywhere: the module only executes under explicit
   invocation (scheduled task or local shell). No scheduler, no trigger
   endpoint changes.

Scope boundaries: ops tooling, not product (no UI, no new API); no
change to graph/node semantics; the demo draft lingers until the
founder retires or approves it (stated, not hidden).

## Verification

- Executable: offline test drives the module's `run_once()` with stub
  LLM + MemorySaver (gate pauses as designed); `python -m pytest
  pipeline/tests -q` green; `cmd /c "npm run verify"` green.
- Live: one-shot scheduled task on production prints board bytes +
  version + draft id + paused gate; tasks deleted immediately after.
