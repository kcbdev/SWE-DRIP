# PBI-032: Fourthwall webhook + Analytics trigger (A17)

## Directive

Implement `POST /api/webhooks/fourthwall`: authenticate events (signature/secret verified against the configured FW webhook secret), reject unverifiable payloads, dedupe by event id for idempotency, and dispatch order/checkout events to `api/app/analytics_trigger.py` — the shared trigger module used by both webhooks and scheduled catch-up pulls — which updates the affected collection's KPI status. Tests: bad signature → 401/403; duplicate event → single processing; valid event → trigger invoked with the right collection mapping; unknown event type → logged no-op.

Scope boundaries: no writes to Fourthwall; no direct KPI computation duplication (delegate to PBI-031's analytics module); no polling loop implementation (scheduled pulls are a trigger-path detail behind the same module).

## Refinement rule

- If Fourthwall's webhook signature scheme differs from the assumed HMAC/secret model, stop and record the verified scheme in the module + spec Decisions — never accept unauthenticated events as a workaround.
- Event id storage for dedupe is minimal (id + received-at); do not build a second event store beyond that.
