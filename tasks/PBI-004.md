# PBI-004: Auth backend — Better Auth runtime + FastAPI session validation + RBAC

## Directive

Set up Better Auth inside `control-panel/` with the Postgres adapter and the admin plugin configured with custom roles `admin`/`operator`/`viewer`; disable public signup; wire `/api/auth/*` routes. In FastAPI, implement `api/app/auth.py` (validate the `better-auth.session_token` cookie: HMAC-SHA256 signature check with `BETTER_AUTH_SECRET`, then `session` row lookup in Postgres; resolve actor + role) and `api/app/rbac.py` (role dependencies); add a protected `GET /api/me` returning actor + role; add the DB layer (`api/app/db.py`) and the migration that creates Better Auth's tables (use Better Auth's own schema generator/migrate). Write `docs/adrs/ADR-003.md` recording the auth architecture and the same-origin `/api/*` traffic decision.

Scope boundaries: no UI beyond what Better Auth requires; no user-management endpoints yet (PBI-005); no audit rows yet (audit-log spec). Tests must be offline — DB-dependent tests skip cleanly without `DATABASE_URL`.

## Refinement rule

- If the Better Auth cookie format or DB schema diverges from the documented `token.signature` + `session` table shape, stop and update ADR-003 with the verified mechanics before continuing — do not fall back to a second auth implementation.
- Role naming must stay exactly `admin`, `operator`, `viewer` everywhere (DB, API, UI).
