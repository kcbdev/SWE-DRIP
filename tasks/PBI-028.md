# PBI-028: Runs + replay API

## Directive

Implement `api/app/routers/runs.py`: `GET /api/runs` (filters: collection, status, date; Viewer+) with current node/status/timestamps; `GET /api/runs/{id}` (Viewer+) returning the typed per-node state history read from the checkpointer in the locked 11-node order; `POST /api/runs/{id}/replay` `{node}` (Admin/Operator) resuming from that node's recorded state without re-executing upstream nodes, writing an audit row (actor, run, node). Tests: fixture listing/filtering; detail maps checkpointer state per node; replay asserts upstream nodes are not invoked (mocked graph) and node order matches the locked list; role matrix.

Scope boundaries: no UI (PBI-029); no duplicate run-state store; no custom re-run engine (use the checkpointer).

## Refinement rule

- If the checkpointer's node history format makes a node's state ambiguous, surface the raw state with an explicit "unknown shape" marker rather than guessing in the API layer — and flag for a pipeline state-schema amendment.
- The replay endpoint must be idempotent-safe: a duplicate replay request while a replay is running returns the in-flight reference, never starts a second execution.
