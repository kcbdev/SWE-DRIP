# PBI-052: Collection research UI (board, inspiration, gate)

## Directive

Give the founder the research surface in the Control Panel:

1. `/collections/[id]/research` view (or a tab on the existing detail —
   whichever the codebase favors, one place only): mood-board sheet
   display (same-origin images), inspiration asset grid (upload form +
   link+note form, delete with confirm), locked directives panel
   (descriptors, palette, avoid list, board version), lineage/diversity
   flags with reasons, and the CEO gate actions (approve / edit-and-
   approve / reject) reusing the existing lifecycle endpoints.
2. Research-run trigger + status (started, synthesizing, board rendering,
   awaiting-approval) with per-node logs beside it (PBI-042 patterns —
   State|Logs tabs, not a second log viewer).
3. Viewer sees everything read-only (boards, directives, flags); Admin
   edits. Server-side RBAC remains the enforcement point.
4. A styles-manager section (the manageable repo from PBI-048): list the
   7 styles with definitions + version, create/edit forms (Admin, audited,
   name-uniqueness enforced, spec-C1 revalidation of affected contracts
   surfaced, never silent), viewer read-only.
5. Component tests: board renders image rows; upload without a file is
   impossible via the UI; gate actions confirm-gated; viewer shows no
   edit controls; diversity flag renders its reason.

Scope boundaries: no new API behavior (PBI-049/050 own the endpoints);
no code execution or free-form scripting anywhere; no per-run overrides
bypassing the store.

## Verification

- Contracts C3 (UI half), C4 (gate half) of the spec.
- Executable: `npx vitest run` green; `cmd /c "npm run verify"` green.
- Manual: curate 3 references → run research → board displays → approve → collection goes active with visual fields filled.

## Refinement rule

- The UI must never offer a value the API would reject (catalog-backed
  pickers, schema-shaped forms). If an asset endpoint is unavailable,
  disable with a visible reason rather than allowing free text.
