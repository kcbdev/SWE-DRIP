# PBI-049: Inspiration ingest (assets + refs per draft)

## Directive

Let operators attach visual research to a draft candidate:

1. `api/app/inspiration.py` + `api/app/routers/inspiration.py` (new) —
   `POST /api/collections/{slug}/inspiration` (Admin-only, audited):
   multipart image (PNG/JPEG, ≤5 MB, magic-byte validated, stored at
   `{COLLECTIONS_DIR}/<slug>.assets/{uuid}.{ext}` with a provenance sidecar
   `{uuid}.json`: source URL or "upload", note, actor, timestamp) or JSON
   link refs (`{url, note}` appended to the contract's `inspiration_refs`).
   Rejects non-images, oversize payloads, and path traversal loudly.
   `{COLLECTIONS_DIR}` is env-driven with a repo-relative default
   (PBI-053 mounts the volume; this PBI only ever addresses the root
   through the store, never a literal).
   `GET` lists a collection's assets + refs (Viewer+); `DELETE
   /{asset_id}` removes file + sidecar (Admin, audited). No update path.
2. `collections_store.py` — asset refs are filesystem + sidecar truth (no
   new table); contract `mood_board`/`inspiration_refs` edits flow through
   the existing PATCH path (extra-forbid still holds — v2 keys are schema).
3. Tests: upload round-trip (bytes identical, sidecar correct), rejection
   matrix (GIF-as-PNG, 6 MB, `../../` name, link without URL), delete
   removes both files, viewer 403 on writes, audit rows carry paths never
   bytes.

Scope boundaries: no synthesis or board rendering (PBI-050); no web
harvesting (spec out-of-scope — curation-in only); no serving beyond
same-origin static reads under the collection route.
