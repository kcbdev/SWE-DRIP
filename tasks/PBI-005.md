# PBI-005: Login + Users & Roles UI

## Directive

Build the auth-facing Control Panel UI: a login page (email + password via the Better Auth client), a session-aware shell (nav shows the signed-in user and role, with logout), and the Settings → Users & Roles screen (list users, invite user, change role, deactivate) calling the API from PBI-004/this PBI's endpoints. UI role-gating (admin-only controls hidden for non-admins) is cosmetic on top of the server enforcement from PBI-004. Add the user-management endpoints the screen needs (list/invite/change-role/deactivate, all Admin-only) if not already covered by PBI-004's scope — keep actor binding server-side.

Scope boundaries: no password-reset/email flows; no SSO; no audit rows yet. Do not modify `api/app/auth.py` validation mechanics (PBI-004 owns them).

## Refinement rule

- If the invite flow requires an email provider not in scope, create the user with a temporary credential delivered out-of-band and record that in the PBI resolution — do not add an email dependency silently.
- Any new endpoint must carry the same RBAC dependency pattern from `api/app/rbac.py`.
