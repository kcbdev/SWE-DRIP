# PBI-017: SSE live stream

## Directive

Implement `GET /api/stream/runs` (SSE via `sse-starlette`): an in-process broker that the hitl service and graph runner publish run-status/queue deltas to; the endpoint pushes events to authenticated sessions (Viewer+), with heartbeats and clean disconnect handling. Event shapes documented in the module (event type, run/approval id, status delta). Tests: broker publish/subscribe; client receives events in order; unauthenticated stream rejected; heartbeat emitted.

Scope boundaries: no UI consumption (PBI-018); no WebSocket; no cross-process broker (single deployable per ADR-002).

## Context

- Spec: `specs/hitl-approvals/spec.md`
- Depends on: PBI-016
- Files/modules touched: `api/app/stream.py`, `api/app/routers/stream.py`, `api/app/hitl.py` (publish hooks only), `api/tests/test_stream.py`
- Plane: (pending sync)

## Verification

- Contract C5 (backend half) of the spec.
- Executable: `python -m pytest api/tests -q` green (broker tests with an async client); `cmd /c "npm run verify"` green.
- Manual: connect to the stream; trigger a decision from another terminal; the event arrives without polling.

## Refinement rule

- If SSE through the dev proxy (Next rewrite) fails in practice, record the finding and wire the dev stream directly (still same-origin in prod) — do not switch to WebSocket without an ADR.
- No event payload may carry secrets or full state dumps; deltas only.
