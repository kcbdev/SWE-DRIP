# PBI-040: OpenRouter model catalog API + write-time validation

## Directive

Make a dead model ID impossible to save:

1. `api/app/model_catalog.py` — fetch `https://openrouter.ai/api/v1/models`, cache in memory with a TTL, expose `list_models(query=None)`, `model_exists(id)`, and a `closest(query, limit)` helper for rejection messages. Never raises into a request: a fetch failure degrades to the last good cache, or an explicit unavailable flag when there is no cache.
2. `GET /api/agents/models` (Viewer+) — catalog list for the UI picker: `id, name, context_length, prompt/completion price per M, input modalities`. Supports `?q=` filtering.
3. `GET /api/agents/models/{id:path}` (Viewer+) — one model's detail.
4. Enforcement: any write that sets a model (PBI-038's config PATCH) rejects an ID not in the catalog with `422` naming the closest matches. This is the contract that prevents the first-live-run failure class from recurring.
5. Tests: offline catalog read; filter; `model_exists` true/false; PATCH with a dead ID → 422 + suggestions; PATCH with a live ID → accepted; catalog unavailable → reads still serve from cache and the *write* path reports it cannot verify rather than accepting blindly.

Scope boundaries: no UI (PBI-041); no pricing-driven auto-selection; do not call OpenRouter with credentials (the models endpoint is public) and do not send the OpenRouter key to it.

## Verification

- Contract C3 of the spec.
- Executable: `python -m pytest api/tests -q` green with the catalog mocked (no network in gates); `cmd /c "npm run verify"` green.
- Manual: `GET /api/agents/models?q=gemini` returns live rows; `PATCH` with `google/gemini-2.0-flash-001` (the ID that broke the first live run) is rejected with suggestions.

## Refinement rule

- A stale cache may serve *reads*; it must never authorise a *write*. If the catalog cannot be verified at write time, refuse and say so.
