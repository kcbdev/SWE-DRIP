# PBI-021: Collections UI — list, detail, create/edit, lifecycle actions

## Directive

Build the Collections screens: list with status filters (active / candidates / retired); detail showing contract fields as a readable form (color chips for the palette, placement templates as per-design-type diagrams, lifecycle countdown, products grid, KPI chart slot with explicit empty state); create/edit form mapping 1:1 to the schema (no raw YAML); approve/retire actions with confirmation and, for retire, a survivor-product selector.

Scope boundaries: no approvals-queue duplication (deep-link to Approvals where relevant); no KPI analytics implementation (chart may render the empty state until catalog-analytics lands).
