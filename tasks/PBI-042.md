# PBI-042: Per-node run logs + run visualisation

## Directive

Make a live run debuggable from the UI without container logs:

1. `pipeline/runlog.py` + migration `0006_run_logs.sql` — structured rows `(id, run_id, node, level, message, detail_json, created_at)`. A `RunLogger` is injected via `config["configurable"]["run_logger"]` (same pattern as `cost_engine`) so nodes stay testable and offline runs use an in-memory logger.
2. Nodes emit events at meaningful boundaries: start, model+params actually used, token usage, cost row written, validation rejection, degraded read, skip (disabled), error — with the node's own reason text. Secrets are never logged (a redaction test over a log with token-looking text).
3. API: `GET /api/runs/{run_id}/logs` (Viewer+, filters: node, level, since) and `GET /api/runs/{run_id}/logs/stream` reusing the existing SSE broker so logs stream live.
4. Runs screen: replace the flat node list with a **status-coloured flow** (complete / current / awaiting-approval / failed / not-reached) showing per-node duration, and a per-node log panel beside the existing state inspector. Run list gains search + filters (collection, status, date) and the resolved-config summary (model per node) so a run explains itself.
5. Tests: node emits expected rows; redaction; filters; a failed node's log entry is present and names the reason; the flow component renders each status variant.

Scope boundaries: no log retention/rotation policy beyond a documented cap; no changing the audit log (different surface, see spec Decisions); logs never accept operator-supplied template strings.

## Refinement rule

- Per-node logs are diagnostic, not the audit trail. Never write an audit row from a node log path, and never let a log failure break a run (best-effort, like the auth-event hook).
