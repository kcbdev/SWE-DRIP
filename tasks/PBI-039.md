# PBI-039: Prompt overrides + effective prompt version

## Directive

Make node prompts operator-editable **without breaking calibration honesty**:

1. `pipeline/prompts.py` — single registry of the built-in prompt builders (trend clustering, listing copy, design spec, QC rubric) with a stable `prompt_key` per node and a `prompt_version(node)` that hashes the effective prompt text.
2. `prompt_override` from the resolved node config (PBI-038) takes precedence over the built-in builder for `trend_research`, `listing_copy`, `design_spec`, `aesthetic_qc`.
3. `aesthetic_qc`: the verdict must carry `prompt_version` (not just `rubric_version`), and `prompt_version` must change whenever the effective prompt changes (base or override). `designs.py` calibration compares like-with-like or flags the mismatch explicitly.
4. `MAX_REGEN_RETRIES` / `PASS_THRESHOLD` stay code constants in `rubric.py` — promoting them to config is a separate decision (PBI-013 refinement rule); do not move them here.
5. Tests: no override → identical prompt to today; override replaces the prompt; version changes with an override and is stable without one; calibration flags a version mismatch rather than reporting agreement; a prompt containing secrets-looking text is not logged.

Scope boundaries: no UI (PBI-041); no model/threshold config; no prompt templating language (plain text substitution only).

## Verification

- Contracts C4 of the spec (and the C2 freeze rule).
- Executable: `python -m pytest api/tests pipeline/tests -q` green; calibration suite still passes with no overrides.
- Manual: override the QC prompt → next run's verdict carries a different `prompt_version` and the calibration view reports the mismatch instead of agreement.

## Refinement rule

- Calibration pins are evidence. If an override makes a pin unusable, the calibration view must say so — never silently compare a pinned response against a changed prompt.
