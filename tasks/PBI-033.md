# PBI-033: Settings — HITL toggles, brand-lock constants, integrations status

## Directive

Create the `settings` table (key/value JSON) and `api/app/settings.py` (typed accessors + defaults); `GET/PATCH /api/settings/hitl` (per-node on/off; PATCH Admin, confirmation-required, audited), `GET/PATCH /api/settings/brand` (brand-lock constants; PATCH Admin + founder-gated confirmation + audit), `GET /api/settings/integrations` (Fourthwall MCP connection state, OpenRouter key presence — booleans only, never values). Add `pipeline/settings.py` and wire the pipeline's HITL flag resolution to the settings store (defaults preserved when the store is absent). Build the Settings screen: HITL toggles with a confirmation dialog per change, brand-lock constants view, integrations status section.

Scope boundaries: no credential entry/rotation UI; no budget engine; no agent roster (PBI-034). Toggling must not require any pipeline structural change (pipeline-core C2).

## Refinement rule

- If the pipeline cannot read the settings store at run time (e.g. different process boundary appears), stop and amend ADR-002 before adding a sync mechanism — no shadow config files.
- The integrations endpoint must never leak values; any accidental secret exposure is a defect, not a follow-up.
