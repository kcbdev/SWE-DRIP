# PBI-029: Runs UI — step tracker + node inspector + replay

## Directive

Build the Runs screens: list (filters, current node/status, links); run detail with the horizontal eleven-node step tracker (failed/pending/complete states), each node clickable to a panel showing its recorded state at that point; a "Replay from here" action on any node with confirmation, wired to the replay API and showing a pending state until the backend confirms.

Scope boundaries: no state editing; no QC decision actions (design-qc owns those); display order fixed to the locked node list.

## Context

- Spec: `specs/traceability/spec.md`
- Depends on: PBI-028, PBI-001
- Files/modules touched: `control-panel/app/runs/**`, `control-panel/components/runs/**`, `control-panel/tests/*`
- Plane: kcb/SWDRP-29

## Verification

- Contracts C2, C3 (UI path), C4 of the spec.
- Executable: component tests with mocked API (tracker renders 11 nodes in order; node panel shows state; replay confirm + pending + error recovery); `cmd /c "npm run verify"` green.
- Manual: inspect a real run, expand a mid node, replay it, confirm the tracker updates without upstream re-execution.

## Refinement rule

- If the API returns a node set that differs from the locked list, the screen must show an explicit mismatch warning rather than rendering a silently wrong tracker.
- Node state panels render JSON with the same diff/readability conventions as the audit viewer; no raw dumps without affordances.
