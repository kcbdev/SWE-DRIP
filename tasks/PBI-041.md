# PBI-041: Agents screen — model picker, params, prompt editor

## Directive

Give the founder the control the API now exposes:

1. `/agents` roster gains, per node: current effective model (overridden vs default, clearly distinguished), a **model picker** populated from `GET /api/agents/models?q=` (searchable, shows price per M and input modalities), and generation params (temperature, max tokens) with defaults shown.
2. A **prompt editor** per node showing the built-in prompt read-only alongside an optional override (enabled/disabled toggle), with the effective `prompt_version` displayed so an override's impact on calibration is visible at the point of editing.
3. An **enabled/disabled** toggle per node, documented as "skips this node's model call — the node still records that it was skipped".
4. Every save requires a **cost-impact note** (existing convention) and surfaces the before→after diff on success.
5. Viewer sees everything read-only (no pickers/editors); Admin can edit. Server-side RBAC remains the enforcement point.
6. Component tests: picker renders catalog rows; selecting an unknown model is impossible via the UI; override toggle reveals the editor; viewer role shows no edit controls; cost-impact note is required.

Scope boundaries: no code execution or free-form scripting in prompts; no per-run overrides; no changes to budget-cap editing (already shipped).
