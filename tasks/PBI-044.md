# PBI-044: MCP mount + read tools + graph inspection

## Directive

Mount the operator MCP doorway (read-only) reusing the REST implementations:

1. `api/app/mcp/server.py` — FastMCP server mounted in `api/app/main.py` at `/mcp` (Streamable HTTP, same deployable); every request authenticates via PBI-043's `require_token("read")`. Tool errors surface as MCP errors with the REST status meaning preserved (404/422/503 wording, never tracebacks).
2. `api/app/mcp/tools_reads.py` — read tools that call the same functions the routers call (no re-implementation): `runs_list`, `run_detail`, `run_logs` (node/level/since/limit), `approvals_queue`, `agents_roster`, `models_search` (catalog `?q=`), `prompt_meta`, `collection_get`, `audit_query`, `calibration_get`. Shapes identical to REST; prompt text and token values never travel (reuse the REST trims).
3. `api/app/mcp/tools_graph.py` — `graph_inspect`: locked `NODE_ORDER`, the `register_node` edge order, per-node state key (`NODE_STATE_KEY`), and config source (routing default vs store override + prompt key/version). Read-only by construction — no parameters that mutate.
4. Tests `api/tests/test_mcp_reads.py` — MCP-conformance over the SDK's in-memory transport (no network, no DB): auth rejection without token, every read tool against fakes, shape-equality with the REST mappers on one fixture each, graph inspection matches `NODE_ORDER`.

Scope boundaries: no write tools (PBI-045); no structural graph mutation (spec C4 — the inspection tool reports, never edits); no new state store.
