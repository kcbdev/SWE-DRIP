# PBI-060: One-shot item-run CLI (first live shirt)

## Directive

Trigger one real item pipeline run where the models, database, and
volumes live (production container) without moving secrets anywhere:

1. `pipeline/run_cli.py` — `python -m pipeline.run_cli COLLECTION
   [--demo] [--design-type X] [--briefs JSON]`: validates briefs and
   design_type with the production code paths (`validate_briefs`,
   `DESIGN_TYPES`), then delegates to `CheckpointerRunStarter` — the
   exact starter `POST /api/runs` uses, so cost-guard read, frozen HITL,
   run logging, and the `fw_live` phase lock behave identically. Polls
   the checkpointer to paused/terminal (deadline ~4 min) and prints a
   JSON summary (run_id, status, current node, design_id, errors).
2. `--demo`: uses one embedded terminal-themed brief
   (`live-1 / Terminal pulse`, scores inside the locked ranges) and
   ensures the `live-review` demo seed carries one `hero-icon` placement
   template — a runnable demo shape only; real drafts and the research
   assembler are untouched.
3. No auto-run anywhere: explicit invocation only (scheduled task or
   local shell). Gates pause for the founder in UI exactly like
   API-started runs (`contract_approval`, `publish_gate` default ON);
   `fw_create` records its phase-lock error instead of publishing.

Scope boundaries: ops tooling, not product (no UI, no new API, no
graph/node changes); no spend beyond the one requested run; the demo
brief/template live in the module as reviewable constants.

## Verification

- Executable: offline tests for usage/brief/design-type validation
  (the heavy path reuses the API-proven starter verbatim);
  `python -m pytest pipeline/tests/test_run_cli.py api/tests -q` green;
  `cmd /c "npm run verify"` green.
- Live: deploy, reseed demo, one-shot task prints a run that reaches
  the first gate; founder approves gates in UI to shelf; tasks deleted
  after.
