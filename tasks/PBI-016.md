# PBI-016: HITL resume service + approvals queue API

## Directive

Create the `hitl_approvals` table migration (`id, run_id, node, status, reviewer_user_id, note, decided_at`) and `api/app/hitl.py`: gather open interrupts from the LangGraph checkpointer (interrupted runs + their node payloads) and merge them with index rows into queue items. Implement `GET /api/approvals` (Viewer+) and `POST /api/approvals/{id}/decision` (Admin/Operator) accepting `{action: approve|reject|regenerate, note?}`; the decision resumes the paused run via `Command(resume=...)` exactly once (idempotent — a duplicate returns the recorded decision), updates the index row, and writes an audit row via the shared writer. Tests: resume dispatch with a mocked graph; idempotency; role matrix; audit payload; queue aggregation shape.

Scope boundaries: no SSE (PBI-017), no UI (PBI-018); do not build a second queue model. The decision action set is fixed: approve/reject/regenerate.

## Refinement rule

- If the checkpointer cannot enumerate interrupted runs efficiently, add the minimal query surface needed and record it — do not mirror full run state into the index table.
- `Command(resume=...)` payload shapes must match the interrupt payloads defined by pipeline-core; mismatches are pipeline-core bugs, not silently patched here.
