# PBI-048: Style repository + contract schema v2

## Directive

Lock the creative vocabulary in a manageable repo, not in code:

1. `collections/styles.yaml` (new, committed seed) — file-level `version`
   plus exactly 7 entries, each `{name, graphic_definition}`. Names are
   proposed here and ratified by the founder at review (taste gate — this
   PBI does not close without it); changing the list afterwards is a spec
   amendment.
2. `pipeline/styles.py` (new) — loader (`load_styles()`,
   `style_names()`, `get_style(name)`) reading the YAML (single source;
   agents and validators read through it, nothing hardcodes names).
3. `api/app/collections_schema.py` — v2 visual fields, all optional with
   empty defaults: `style_descriptors: list[str]`, `mood_board: list[str]`
   (relative artifact refs only — no URLs, no absolute paths),
   `inspiration_refs: list[{url, note}]`, `avoid: list[str]`,
   `board_version: int = 1`. `style_archetype` stays a non-empty string
   at the schema level (drafts carry free member styles); the repo check
   lives in the approve-time completeness gate
   (`_completeness_errors`: unknown archetype → 422, same as missing
   palette/thresholds) — locking happens at approval, never at drafting.
   Every v1 contract still validates byte-identically (asserted).
4. `pipeline/nodes/contract.py` — `CONTRACT_KEYS` gains the v2 keys with
   draft defaults (`[]`/`{}`/`1`); `validate_contract` accepts them;
   drafts never invent visual content (empty placeholders, same rule as
   palette/thresholds today).
5. Tests: 7 locked names enforced at approve (unknown archetype → 422,
   locked name passes); repo loader reads the YAML (missing file is loud,
   never silent defaults); v1 fixture validates unchanged; v2 fields
   round-trip; mood-board ref rejects absolute paths and URLs.

Scope boundaries: no management API/UI for styles (PBI-052 owns the UI;
creation stays founder-gated); no research graph (PBI-050); no QC
changes (PBI-051); agents read the repo — minting styles stays human.

## Refinement rule

- If the founder renames a style, update the YAML, the spec, and the
  loader test together — a renamed style without all three is a defect.
