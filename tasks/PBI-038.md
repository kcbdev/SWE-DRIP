# PBI-038: Per-node runtime config store + resolution

## Directive

Make each node's runtime behaviour store-backed and layered:

1. `pipeline/node_config.py` — the single resolution point. Declares per-node defaults (`model` from `routing.MODEL_FOR_NODE`, `params`, `prompt_override: None`, `enabled: True`) and resolves them against the settings store key `node_config`. Resolution is layered: **code defaults < store override**; an empty store must behave exactly as today. Export `resolve_node_config(node) -> NodeConfig` and `resolve_all_node_configs()`.
2. `api/app/settings_store.py` — typed accessors for `node_config` (get/set/clear per node), reusing the existing JSON settings row.
3. Run wiring: `CheckpointerRunStarter.start()` resolves the config once and passes it as `config["configurable"]["node_config"]`; it is also recorded in run state so a finished run explains itself.
4. Update `pipeline/routing.py` defaults to the current working IDs (see spec Decisions) — `routing.py` becomes defaults, not the source of truth.
5. Tests: empty store == code defaults (byte-identical); store override wins per field; partial override keeps other fields' defaults; resolution is frozen into config at start; unknown node is loud.

Scope boundaries: no UI (PBI-041); no model validation/catalog (PBI-040); no prompt-override versioning (PBI-039); do not change the 11-node order or HITL semantics.
