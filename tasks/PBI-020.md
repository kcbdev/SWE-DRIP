# PBI-020: Collection lifecycle — candidates, approve, retire + survivor exception

## Directive

Extend the collections API/store with lifecycle: surface Trend-cluster output as draft candidates; `POST /api/collections/{id}/approve` (Admin/Operator) sets `status: active` + `approved_at`, writes audit, and when the candidate corresponds to a paused collection-gate run calls the hitl resume service so the pipeline continues (A8); `POST /api/collections/{id}/retire` (Admin) marks retired with an optional survivor product exception that keeps the named product live and flagged (A9). Tests: candidate creation from a cluster fixture; approve → YAML valid + active + audit + resume dispatched; retire with survivor keeps the product live and flagged; retire without survivor deactivates collection membership.

Scope boundaries: no UI (PBI-021); no KPI-based retirement recommendations (catalog-analytics); resume mechanics stay in `api/app/hitl.py` (call it, don't reimplement).
