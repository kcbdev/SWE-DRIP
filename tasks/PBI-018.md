# PBI-018: Approvals screen (aggregated HITL queue)

## Directive

Build the Approvals screen: tabs (All default, Collections, Designs, Publishes); each row shows what it is, which collection, waiting age, one-click approve, reject-with-note, and a link to the full detail (where it exists); an optimistic "resuming pipeline…" pending state until the backend confirms; live updates via the SSE stream (fallback to manual refresh if the stream is unavailable). Data + actions exclusively through the PBI-016 API.

Scope boundaries: no gate-specific detail views (design-qc/collections specs); no queue mutations outside the decision endpoint.

- Depends on: PBI-016, PBI-017, PBI-001

## Verification

- Contracts C3 (UI path), C5 (frontend half), C6 (UI gating) of the spec.
- Executable: component tests with mocked API/SSE (tabs filter, approve/reject flows, note required on reject, pending state, live insert); `cmd /c "npm run verify"` green.
- Manual: with a paused collection-gate run, approve from the queue → run resumes and the row clears.

## Refinement rule

- Reject must require a non-empty note (feeds regeneration). If a gate's payload lacks the note field, stop and flag the pipeline contract rather than shipping a silent no-op.
- The screen commits no optimistic data it cannot reconcile; failed decisions must surface an error and restore prior state.
