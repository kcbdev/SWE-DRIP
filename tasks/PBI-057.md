# PBI-057: Dev auth bypass for UI verification (never production)

## Directive

While developing, UI verification needs an admin session without real
credentials. `SWE_DRIP_DEV_AUTH_BYPASS` (new, empty by default):

1. Missing, empty, whitespace-only, or `false` (case-insensitive) →
   bypass OFF: zero behavior change on either runtime.
2. An email (`local@domain`, no spaces) → bypass ON with that identity:
   - API (`get_current_actor`): returns
     `Actor(user_id="dev-bypass", email=<email>, role="admin")` with no
     session required. Audits carry the `dev-bypass` identity — traceable,
     never a real user id.
   - Panel: middleware skips the login redirect; `auth-client.ts` wraps
     `useSession` to return a synthetic `{user: {email, role: "admin"}}`
     sourced from a same-origin `GET /api/dev/session` route (server env
     read, 401 when off). All pages untouched — single-module change, no
     Better Auth changes.
3. Anything else (e.g. `true`, `1`, `not-an-email`) → loud startup
   failure, never a silent off or a guessed identity.
4. Production refusal: `APP_ENV=production` (new API setting; DEPLOY
   already sets it) + bypass enabled → the API refuses to boot
   (RuntimeError at startup). The panel ignores the flag under
   `APP_ENV=production` (defense in depth; the API refusal is the hard
   boundary).

Scope boundaries: dev-only, never set in Coolify (`.env.example` keeps
an empty commented entry; the lint secret-scan stays green); admin role
only (no operator/viewer impersonation); no credential issuance.

## Verification

- Executable: resolve matrix (off/on/garbage/production) unit-tested;

- Manual: local UI pass over PBI-052 with the bypass on (research view
